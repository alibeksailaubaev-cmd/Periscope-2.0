# Executive Dashboard — биобезопасность и нагрузка персонала

Материалы для обоснования второй штатной единицы службы биобезопасности:
интерактивный дашборд нагрузки и аналитическая записка с ТЗ на анимационные ролики.

## Файлы

- `BiosecurityExecutiveDashboard.jsx` — компонент в одном файле (React + Framer Motion + Highcharts + lucide-react + Tailwind). Готов к вставке в Claude Artifact или в любой React/Vite/Next проект.
- `report.html` — аналитическая записка для руководства: расчёт нагрузки, узкие места и ТЗ на два ролика.
- `dashboard.html` — автономная сборка (все библиотеки и фон внутри, без CDN и внешних запросов). Открывается двойным кликом.
- `assets/external-flow.mp4` — **не в репозитории**: скачайте ролик из карточки Higgsfield и положите сюда, дашборд подхватит его автоматически (см. `assets/ГДЕ-ВИДЕО.md`).
- `assets/higgsfield-bg.b64.txt` — светлый премиальный фон, сгенерированный Higgsfield (nano_banana_pro), сжат в JPEG 1.9 КБ и вшит в компонент как data-URI.

## Зависимости для проекта

```bash
npm i react react-dom framer-motion highcharts highcharts-react-official lucide-react
```
Tailwind CSS должен быть подключён в проекте (в Claude Artifact он есть по умолчанию).

## Структура страницы

1. **Хедер** — статус «Критическая перегрузка» с пульсирующей точкой, переключатель периода (День / Неделя / Месяц), тема, кнопка «Аргументация для руководства».
2. **KPI** — загрузка 185%, покрытие внешнего контура 55%, объём задач за период, дефицит штата +2.
3. **Два контура** — слева внешний, справа внутренний. У каждой карточки своя живая мини-сцена; клик раскрывает каскадный список только своих направлений, сгруппированных по типу.
4. **Нагрузка** — все 26 направлений слетаются к центру и садятся на двух действующих специалистов, рядом — две пунктирные вакансии. Поток непрерывный и равномерный (задача стартует каждые `4.6 / 20` с), кольцо задач медленно вращается, стопка над головами растёт пружиной, вокруг ядра расходятся волны давления, шкала загрузки перехлёстывает отметку 100%.
5. **Карта перемещений внутреннего контура** — склад, инкубатор, АТЦ, бройлерные площадки и офис; по 6 маршрутам ездят грузовики (SVG `animateMotion`), на точках пульсируют маркеры «здесь нужен специалист», а силуэты двух сотрудников пытаются уйти из офиса и растворяются на полпути.
6. **Аналитика Highcharts** — входящий объём против ёмкости; график перестраивается при выборе контура и периода.

## Модель данных

Все показатели вычисляются из единой таблицы `TASKS`:

| Показатель | Значение | Откуда |
|---|---|---|
| Направлений контроля | 29 | 14 внешних + 15 внутренних |
| Объём задач | 160,5 нормо-часа/нед | сумма `hours` |
| Ресурс службы | 80 ч/нед | `STAFF × HOURS_PER_STAFF` (2 специалиста) |
| Фактически закрывается | 71,9 ч | `hours × cov` |
| Загрузка | 201 % | 160,5 / 80 |
| Общий охват | 45 % | 71,9 / 160,5 |
| Охват внешнего контура | 37 % | 30,8 из 83,5 ч |
| Охват внутреннего контура | 53 % | 41,1 из 77,0 ч |
| Дефицит штата | +2 единицы | ⌈160,5 / 40⌉ − 2 |
| Загрузка после найма | 100 % | 160,5 / 160 |

Оба контура загружены из «Схемы процессов и подпроцессов» службы: 14 внешних и
15 внутренних процессов, у каждого — поле `sub` с подпроцессами из документа
(их показывает третий уровень интро). Проценты охвата (`cov`) — фактические
данные службы; `hours` — экспертная оценка трудоёмкости, квартальные и месячные
работы амортизированы на неделю.

Восемь процессов, которых не было в прежней модели, получили трудоёмкость
ориентировочно и охват 0 % — их нужно подтвердить у службы:
- внешний контур — разработка документов ББ/БЗ, требования к санобработке,
  работа с МИО и ветслужбами, международное сотрудничество, внешнее обучение;
- внутренний контур — внутренний входной контроль, ККЗ, внутренний пест-контроль.

Из прежней внутренней модели ушли «Учёт МиДС» и «Контроль ситуации внутри
объекта» — в схеме процессов их нет; «Аудиты внутренних площадок» переименованы
в «Аудиты площадок и территории», «АТЦ» — в «Парк АТЦ», «Склад лузги» расширен
до «Склады» (весь складской контур, а не только подстилка).

Маршруты перемещений (6 маршрутов, 20 рейсов в сутки) задаются массивом `ROUTES` (путь SVG, груз, число рейсов),
объекты площадки — `SITES`. Чтобы изменить цифры, правьте только эти таблицы
и константы `STAFF` / `HOURS_PER_STAFF` — весь интерфейс пересчитается сам.
