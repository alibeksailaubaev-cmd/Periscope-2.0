# Periscope 2.0

В репозитории два самостоятельных приложения:

1. **Камера фиксации людей в очках** — веб-приложение на Python + Flask с
   детекцией лиц и очков в реальном времени, автоснимками и журналом событий.
2. **Веб-клиент Periscope** — статический фронтенд в стиле Periscope (видео, чат,
   лайки) с serverless-бэкендом на Vercel.

---

# Часть 1. Камера фиксации людей в очках (Python + Flask)

Подключается к веб-камере, телефону (IP Webcam) или IP-камере по RTSP/HTTP,
находит лица, определяет наличие очков, рисует зелёную рамку с надписью
**«В ОЧКАХ»**, автоматически сохраняет кадр в `static/captures/` и пишет событие
в журнал `events_log.json` / `events.csv`. Управление — через дашборд в браузере.

![Стек](https://img.shields.io/badge/stack-Flask%20%7C%20OpenCV%20%7C%20MediaPipe-4f8cff)

## Возможности

- **Источники видео:** локальная веб-камера (`0`, `1`, …), HTTP-поток телефона
  (`http://192.168.0.10:8080/video`), RTSP IP-камеры, а также видеофайл — удобно
  для тестов.
- **Детекция лиц:** MediaPipe Tasks (FaceDetector + FaceLandmarker) с
  автоматическим откатом на MediaPipe Solutions, OpenCV YuNet (DNN) и каскады
  Хаара. Приложение поднимется на любой машине, даже без MediaPipe.
- **Детекция очков:** анализ краёв (Sobel) в зонах переносицы, верхнего и нижнего
  ободка и дужек у висков. Пороги нормируются по «шумности» кожи щеки, поэтому
  детектор устойчив к шумной картинке с IP-камеры.
- **Сглаживание по времени:** медиана оценок за последние кадры + гистерезис —
  статус не мигает между «В ОЧКАХ» и «БЕЗ ОЧКОВ».
- **Защита от спама снимками:** настраиваемый cooldown (по умолчанию 4 секунды)
  общий и отдельно для каждого отслеживаемого человека.
- **Журнал:** `events_log.json` и `events.csv` с полями `ID`, `Дата и время`,
  `Статус`, `Имя файла фото`, `Уверенность распознавания (%)`. Отчёт скачивается
  в CSV, JSON или XLSX.
- **Дашборд:** живое видео с рамками, плашка статуса, панель подключения,
  галерея последних фиксаций, таблица логов, просмотр фото в полный размер.

## Быстрый старт

```bash
git clone https://github.com/alibeksailaubaev-cmd/Periscope-2.0.git
cd Periscope-2.0

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python app.py                    # веб-камера ноутбука
```

Откройте <http://localhost:5000>.

При первом запуске приложение скачает модели детекции (~4 МБ) в папку `models/`.
Если интернета нет — оно автоматически перейдёт на более простой встроенный
детектор, всё остальное продолжит работать.

### Параметры запуска

```bash
python app.py --source 0                                  # веб-камера №0
python app.py --source http://192.168.0.10:8080/video     # телефон, IP Webcam
python app.py --source rtsp://user:pass@192.168.0.64:554/Streaming/Channels/101
python app.py --port 8080 --cooldown 6 --mirror           # свой порт и настройки
python app.py --no-autostart                              # не подключаться сразу
```

| Флаг | Значение |
|------|----------|
| `--source` | номер камеры или URL потока (по умолчанию `0`) |
| `--host` / `--port` | адрес и порт сервера (`0.0.0.0:5000`) |
| `--cooldown` | пауза между автоснимками в секундах (по умолчанию 4) |
| `--sensitivity` | чувствительность детектора очков, `0..1` (по умолчанию 0.5) |
| `--mirror` | зеркалить кадр (удобно для фронтальной камеры) |
| `--no-autostart` | не подключаться к камере при старте |
| `--debug` | режим отладки Flask |

Те же параметры можно менять на лету прямо в интерфейсе.

## Подключение телефона как камеры

1. Установите на Android приложение **IP Webcam** (или **DroidCam**).
2. Телефон и компьютер должны быть в одной Wi-Fi-сети.
3. Запустите в приложении «Start server» — оно покажет адрес вида
   `http://192.168.0.10:8080`.
4. В поле «Источник видео» на дашборде введите `http://192.168.0.10:8080/video`
   и нажмите **Подключить**.

Для IP-камер обычно подходит RTSP-адрес из инструкции производителя, например
`rtsp://admin:пароль@192.168.0.64:554/Streaming/Channels/101` (Hikvision) или
`rtsp://admin:пароль@192.168.0.64:554/cam/realmonitor?channel=1&subtype=0` (Dahua).


## HTTP API

| Метод | Адрес | Назначение |
|-------|-------|------------|
| `GET` | `/` | дашборд |
| `GET` | `/video_feed` | MJPEG-поток с рамками и статусом |
| `GET` | `/api/status` | состояние потока, найденные лица, статистика |
| `POST` | `/api/connect` | `{"source": "0"}` — подключиться/переподключиться |
| `POST` | `/api/disconnect` | остановить поток |
| `GET`/`POST` | `/api/settings` | cooldown, чувствительность, автоснимки, зеркало |
| `POST` | `/api/snapshot` | сохранить текущий кадр вручную |
| `GET` | `/api/events?limit=100` | последние события журнала |
| `POST` | `/api/events/clear` | очистить журнал (`{"delete_photos": true}` — вместе с фото) |
| `GET` | `/api/export.csv` · `/api/export.json` · `/api/export.xlsx` | выгрузка отчёта |
| `GET` | `/captures/<файл>` | сохранённый кадр |

## Как работает детекция очков

1. Бэкенд находит лицо и ключевые точки (глаза, переносица, брови, край лица).
2. Кадр «выравнивается» по линии глаз, чтобы наклон головы не мешал измерениям.
3. По гладкому участку щеки измеряется уровень шума — от него берётся порог для краёв.
4. В четырёх зонах ищутся длинные горизонтальные края (оправа): переносица,
   верхний ободок над глазами, нижний ободок, дужки у висков.
5. Сигналы складываются с весами → оценка `0..1`, дальше медианный фильтр по
   последним кадрам и гистерезис (включение при `0.52`, выключение при `0.40`).
6. Решение считается подтверждённым после N стабильных кадров (по умолчанию 3),
   и только тогда сохраняется снимок.

Если в вашем помещении детектор срабатывает слишком редко или слишком часто —
подвиньте ползунок **«Чувствительность к очкам»** на дашборде.

## Требования и заметки

- Python 3.9+ (проверено на 3.11).
- На сервере без графической оболочки замените в `requirements.txt`
  `opencv-python` на `opencv-python-headless`.
- MediaPipe 1.x требует библиотеку `libEGL`; если её нет, приложение само
  переключится на детектор OpenCV YuNet — качество детекции лиц останется высоким.
- Подписи на кадре рисуются через Pillow, поэтому кириллица отображается корректно.
  Если TTF-шрифт не найден, надписи автоматически становятся латиницей.
- Flask запускается в режиме разработки. Для постоянной работы используйте
  production-сервер, например `waitress-serve --port=5000 app:app`.

## Возможные проблемы

| Симптом | Что делать |
|---------|-----------|
| «Не удалось открыть источник» | проверьте URL, логин/пароль камеры и что телефон в той же сети |
| Чёрный кадр с веб-камеры | камеру занял другой процесс (Zoom, браузер) — закройте его |
| Лицо есть, очки не определяются | увеличьте чувствительность, добавьте света, подойдите ближе к камере |
| Слишком много снимков | увеличьте задержку между снимками и число кадров подтверждения |
| RTSP рвётся | приложение переподключается само; для стабильности используйте substream (пониженное разрешение) |

# Часть 2. Веб-клиент Periscope (HTML/JS + Vercel)

Простое веб-приложение в стиле Periscope:

- 🎥 **Окно видео** — трансляция с камеры браузера (`getUserMedia`), кнопка «Начать эфир»
- 💬 **Чат поверх видео** — сообщения всплывают снизу-слева, автоматически исчезают
- ❤️ **Анимированные лайки** — двойной тап по видео или кнопка ❤️ запускает разлетающиеся сердечки

Фронтенд — чистый HTML/CSS/JS без сборщиков и фреймворков. Бэкенд — serverless-функции
Vercel (`/api`), которые хранят чат и счётчик лайков в бесплатной Redis-базе Upstash.

Если бэкенд недоступен (например, вы просто открыли `index.html` локально двойным
кликом), приложение само переключается в demo-режим с имитацией сообщений и лайков —
интерфейс работает и без сервера.

### Структура проекта

```
index.html         разметка страницы
css/style.css       стили (видео, чат, анимация сердечек)
js/app.js           логика: чат, лайки, камера, поллинг API
api/messages.js      serverless-функция: чат (GET/POST)
api/like.js          serverless-функция: лайки (GET/POST)
package.json         зависимости для api-функций
```

### Как бесплатно запустить бэкенд на Vercel без прав администратора

Всё, что описано ниже, делается **через браузер**, без установки чего-либо на компьютер
и без прав администратора. Локально устанавливать Node.js, npm или Vercel CLI не нужно.

#### 1. Залейте код в GitHub

Если репозиторий уже на GitHub — этот шаг пропустите. Если нет — создайте новый
репозиторий на github.com (кнопка "New repository") и загрузите файлы через веб-интерфейс
(«Add file → Upload files») или через `git push`, если git у вас уже настроен.

#### 2. Создайте бесплатный аккаунт на Vercel

Зайдите на **vercel.com** → «Sign Up» → войдите через GitHub-аккаунт. Отдельная установка
программы не требуется — всё работает в браузере. Бесплатный тариф **Hobby** покрывает
задачи такого масштаба.

#### 3. Импортируйте проект

На дашборде Vercel нажмите **Add New → Project**, выберите ваш GitHub-репозиторий и
нажмите **Import**. Vercel сам определит, что это статический сайт с папкой `api/` —
никаких настроек сборки менять не нужно (Build Command и Output Directory можно
оставить пустыми/по умолчанию).

#### 4. Создайте бесплатную базу данных Upstash Redis

Чат и лайки должны где-то храниться между вызовами serverless-функций (сами функции
Vercel «просыпаются» на каждый запрос и не хранят состояние в памяти). Бесплатный
вариант — **Upstash Redis**, у него есть щедрый free-tier и REST API, который отлично
подходит для serverless.

Вариант А — прямо из Vercel:
1. В настройках вашего проекта на Vercel откройте вкладку **Storage**.
2. Нажмите **Create Database → Upstash Redis → Free**.
3. Vercel сам добавит переменные окружения `UPSTASH_REDIS_REST_URL` и
   `UPSTASH_REDIS_REST_TOKEN` в проект — ничего копировать вручную не нужно.

Вариант Б — отдельно на upstash.com:
1. Зарегистрируйтесь на **upstash.com** (тоже через браузер, бесплатно).
2. Создайте Redis-базу (Free plan).
3. Скопируйте `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` со страницы базы.
4. В Vercel: **Project → Settings → Environment Variables** — добавьте эти две
   переменные вручную и нажмите **Save**.

#### 5. Задеплойте

Если вы ещё не нажимали **Deploy** на шаге 3 — нажмите его сейчас. Если деплой уже был
сделан до добавления переменных окружения — зайдите в **Deployments** и нажмите
**Redeploy**, чтобы функции подхватили новые переменные.

Через минуту Vercel выдаст публичную ссылку вида `https://ваш-проект.vercel.app` — сайт
и бэкенд уже работают вместе на одном домене, дополнительная настройка CORS не нужна.

#### 6. Обновление в будущем

Любой `git push` в ветку, привязанную к Vercel-проекту, автоматически запускает новый
деплой — ничего руками пересобирать не надо.

### Важно понимать про serverless и realtime

Функции в `/api` — **serverless**: они не держат постоянное соединение и не умеют
WebSocket-сервер. Поэтому фронтенд получает новые сообщения и лайки через **поллинг**
(`fetch` каждые 2 секунды, см. `js/app.js`) — это бесплатно и укладывается в лимиты
Hobby-тарифа. Если понадобится «мгновенный» realtime (без задержки поллинга), можно
подключить бесплатный тариф стороннего realtime-сервиса (например Pusher или Ably) —
они как раз созданы для push-уведомлений в браузер и тоже не требуют прав администратора
на компьютере, всё настраивается через сайт.

### Локальный просмотр без бэкенда

Просто откройте `index.html` в браузере — интерфейс полностью рабочий за счёт
demo-режима (см. выше). Для локальной проверки самих serverless-функций через Vercel
можно использовать `npx vercel dev` — `npx` не требует прав администратора и ничего не
устанавливает глобально.
